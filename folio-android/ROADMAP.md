# Folio 后续改进计划

更新：2026-10-20。负责人：Fish。本文是开发方向与验收标准，**不代表功能已经完成，也不是发布日期承诺**。先继续验证当前 Android 测试版，再分阶段实现；每阶段由 Fish 做真机体验验收。

## 一、推进顺序

| 阶段 | 核心目标 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：可依赖 | 学校数据真实、同步稳定、时间与学期正确、升级不丢数据 | 同一真实账号连续使用能完成主要流程，失败可恢复；关键回归通过 |
| P1：少操作 | 常用操作直达，减少滚动、重复输入与多级跳转 | 在真机记录操作次数和完成时间，主要流程明显缩短 |
| P2：卡片精品化 | 精修已有核心卡片，再增加一批高质量 2×2 卡片 | 小屏、深色、空数据、交互与真实性逐卡验收 |
| P3：跨平台 | 以 Flutter 为目标，逐步重建可长期维护的客户端 | 代表页面的视觉、手势、原生能力与数据迁移通过对照验收 |
| P4：校园初版 | 完整发布说明、隐私与条款、来源许可审计、反馈闭环 | GitHub先公开测试；校园论坛推广需Fish另行决定 |

跨平台的接口梳理、视觉规范和数据分层可提前进行；大规模重建应建立在稳定的数据契约之上。避免维护两套长期分叉的产品逻辑。

## 二、P0：先让真实功能稳定

1. **教务、学在浙大与实践记点**：逐站验证统一认证、业务站 Cookie、过期重连、验证码回退、官方网页登录返回后的同步。明确区分“真实为空”“尚未同步”“登录失效”“服务异常”，失败不清空已有缓存。并发更新共用认证，限制重试，防止循环登录。
2. **学期、校历与课程**：统一学期标识、校历边界、单双周和课程合并规则；核对连续 6/7/8 节等情况，避免漏课、重复、串学期。保留用户对误排课程的单次、范围、批量本地排除与恢复。
3. **成绩与目标**：准确匹配主修范围和课程学分，缺失数据提示核对而非默认为 0；区间目标以约定的中间值计算，建议绩点先显示清楚；加权均绩作为独立体系，不混入原均绩。只对首次同步之后的新出分或更正发通知。
4. **本地可靠性**：验证覆盖升级、异常退出、时区和跨午夜、系统返回、权限拒绝、断网重试；制定本地数据版本迁移、备份与恢复方案。凭据不得进入日志、AI 上下文或普通导出文件。
5. **AI 可用性**：保留用户自配地址、模型和 Key；补全可靠的流式回答、Markdown、取消与重试。思考区域展示真实可提供的状态或摘要，不伪造推理过程。工具操作仍是草稿→确认→写入；不将事项误判成作业，不执行网页文本里的越权指令。
6. **提醒与后台工作**：明确主动同步和系统后台调度的区别，完善后台同步与通知权限、节电限制下的降级。截止紧急度按“留出完整可工作日”设计，并覆盖凌晨截止，不能机械用剩余24小时替代。

## 三、P1：缩短达到目的的操作次数

计数规则：从当前页面开始，每次点按计一次；额外打开菜单、页面切换、滚动查找、重复填写都单独记录。输入内容本身不凑成大量点击数；另记录总耗时、误触、返回次数。以下为**目标值**，需要先测当前基线。

| 用户要做什么 | 目标路径 | 操作目标 |
| --- | --- | --- |
| 更新当前模块 | 当前页更新按钮→自动检查登录并同步 | 1 次点按；只有额外认证时中断 |
| 从工作台看作业 | 点便签→看科目、标题、描述、文件与链接 | 1 次进入详情，再点链接打开平台 |
| 向空格添加卡片 | 点“+”→选卡片→添加 | 不超过 3 次点按，缩略图上也能滑动 |
| 更换或移除卡片 | 长按→外部编辑操作 | 不在卡片内部常驻省略号；移除可撤回 |
| 新建通用事项 | 常驻入口或AI生成→精简填写/确认 | 常用情形不超过 3 个交互步骤 |
| 找今天下一件事 | 首页右滑当天列→点目标 | 不进入完整日程页也能完成 |
| 返回首页 | 当前页首页按钮，或既定菜单返回手势 | 1 次操作 |
| 切换页面 | 原导航或可选横向模式 | 保持两套逻辑独立；不增加学习负担 |

具体优化：常用操作留在首屏；高级设置折叠；保留用户最近选择，避免反复填同一学期、时长和模型；长文本给按钮让位，按钮不竖排；手指从按钮、缩略图上开始滑动也应正确识别意图。危险或批量动作的必要确认不为减少点击而取消。

动效单独验收：页面随手指连续移动，中途能停、取消、反向；开始与结束都有过渡；快速反复滑动不闪页、不掉状态；尊重系统减少动态效果设置。先测真实设备，再决定弹性和阻尼，不一味加快动画。

## 四、P2：做一批有用、精美的 2×2 卡片

不以数量代替质量。先精修前六张，再逐批扩充到约 12 张精品；已有其他组件保留为可选，避免默认塞满。四格始终由用户自由添加、留空、更换和长按换位。

| 卡片方向 | 真实价值与数据 | 视觉与交互重点 |
| --- | --- | --- |
| 1. 每日压力 | 课程、事项预计耗时与截止；缺少耗时时说明估计依据 | 居中热力图、由小到大图例、今日箭头；色块不描边 |
| 2. 当前日程 | 已过去、正在做、接下来几项 | 正方形视窗聚焦当下；上下逐渐缩小、虚化，保留必要的事件文字 |
| 3. 可用空档 | 未来数日清醒区间内超过可调基线的空档 | 一段空档一块，显示前一天作参照；任务提前完成后及时重新计算 |
| 4. 截止倒计时 | 未完成任务与完整可工作日 | 线段与端点标记，必要时显示实际数字；紧急有层次，点开才看细节 |
| 5. 专注与建造 | 进入专注状态后的本地记录、上周与累计时长 | 数字有装饰，约45分钟形成一座可收藏的小建筑；合理容忍工作操作，不因误判清零 |
| 6. 手机使用 | 系统授权后的七日用量 | 柱图、柔角小三角定位1h；台灯/鲸鱼等可切换反馈，强调鼓励，不羞辱用户 |
| 7. 学期剩余负担 | 剩余计划课时，和动态作业量明确区分 | 像素山/书本数量；镐敲边沿、碎屑飞出，缓存进度，查看时短暂动一下 |
| 8. 重点课复习 | 重要课程、下次上课时间、接触或问答记录 | 低记忆、快上课的往上；AI短问答帮助更新估计，不声称精确测得记忆力 |
| 9. 期末预警 | 考试日期、目标与已有成绩 | 合并时间压力与目标差距，避免只画一个低信息量指示器；不要求手填复习百分比 |
| 10. 一周与累计概览 | 上周/本周/累计专注，已完成事项、课程等 | 分区数字仪表，一个分区对应一种独立用途；点分区直达相关功能 |
| 11. 学业概览 | 学分、各体系均绩、目标进度、考试 | 高密度但层级清楚；尊重隐藏成绩设置，避免在缩略图或分享里泄露 |
| 12. 资讯与收藏 | 有明确来源的新闻、本地收藏 | 少量高质量条目，来源与时间在详情可查；可选来源、离线缓存，未获取不伪造 |

可用空档还需完善任务完成时间与时长数据。记忆卡需问答闭环。期末预警不把没有证据的复习程度伪装成准确数值。这些条件未齐时可先展示真实可用部分，但必须能看懂其边界。

### 每张卡的美术门槛

- 延续已认可的纸感、剪纸、折纸和像素细节：温暖的低饱和配色，直线折面与硬投影，避免通用仪表盘和厚重柔影。
- 同一风格可以使用不同底色区分四格；内容居中，边界圆角与宿主严格吻合，留白有节奏，不以边框代替层次。
- 卡片展示态不常驻标题、说明文案、“未来七天”等提示；选择页和描述页解释功能。需要读懂的日程与数字卡可保留必要短标签，星期用克制的非黑色字形。
- 今日用箭头或块内标记；保留合理的过去参照。装饰为主体服务，不挡便签、不盖数据、不抢点击区域。
- 每张卡至少检查窄屏/常规屏/较宽屏、浅深色、零数据、少量数据、极端长文字、加载失败、编辑态和减少动画。先在真实2×2尺寸看，再看放大稿。

### 继续开放开发者接口

维持 Widget API v1 的稳定 ID、版本、生命周期、权限声明、只读数据快照与订阅清理；内置卡片和外部卡片走同一注册入口。提供完整示例、设计变量、尺寸约束、空状态和兼容性检查。

未来 Flutter 化前先定义与界面技术无关的数据/动作契约。现有 JS 卡片不会自动变成 Flutter 组件：需要评估 WebView 兼容容器与原生组件适配层的成本，并用样例验证。不得以跨平台为由取消外部可添加性，也不承诺无限制远程执行第三方代码。

## 五、P3：跨平台，以 Flutter 为目标

### 先做代表性验证

选择首页对话输入区、2×2热力卡、便签火焰与收纳袋、当天窄列、日程折叠、弹窗/系统返回作为迁移样例。冻结参考截图、颜色、字体、间距、层级及关键动画曲线，在相同逻辑尺寸对照。静态相似之外，还要比较输入键盘、安全区、拖动中断、滚动冲突与长按。

不承诺100%逐像素自动复刻。出现差异由 Fish 体验后决定取舍；未经认可不批量重画已认可界面。

### 再分层迁移

1. 抽离统一数据模型、学期/时间规则、学校适配器、AI工具契约、存储版本和通知状态，补契约测试。
2. 整理可复用设计系统：纸片、粗虚线、按钮、图标、弹窗、反馈、拖动套边、垃圾桶与深色调色板。
3. 先迁移只读页面和工作台样例，验证离线、性能与组件扩展，再迁移登录、AI附件、编辑确认等关键写入流程。
4. Android保留并逐步适配已可用的本机能力；安全迁移普通数据，Key与学校密码不得明文搬运。凭据无法安全迁移时由用户重新授权或输入，并提前说明。
5. Android稳定后评估iOS、桌面和Web。各平台的用量统计、后台运行、通知、相机和身份认证能力单独验证；不能假定同一套权限都可实现。Web无法可靠完成的学校请求要另做经许可的后端方案，不为跨平台偷偷引入集中保存账号密码的服务。

Android优先保持体验连续；其他平台按能力和测试资源逐项进入，不同时承诺全部上线。新旧版本并行验证期要短，并约定唯一的数据规则来源。

## 六、发布前与长期维护

- 整理真实来源和改编范围，保留已有许可与署名，完成第三方素材、字体及服务使用要求审计后再决定公开方式。
- 完善服务条款、隐私说明、反馈入口，准确解释本地存储、学校连接、可选模型、附件发送、权限及删除方式。
- 提供更新说明、升级/回退边界、崩溃诊断与脱敏日志；任何远程统计或错误收集需先明确目的和开关，不能默认上传学业内容。
- 建立固定回归：真实数据正确性、个人数据修改确认、核心操作次数、关键动画、不同尺寸、权限/断网、覆盖安装和数据迁移。
- 发布节奏以“一个可验证的体验改进”为单位。记录用户遇到的问题与修复证据，避免依靠大量代理重写前端或用自动测试替代审美验收。

## 七、下一轮建议先做的五件事

1. 用0.9真机验证教务一键同步、主题系统栏、横向切页和返回，记录仍失败的具体入口。
2. 对“看下一件事、添加事项、刷新作业、配置卡片”测一次操作基线，先减少最明显的跳转与滚动。
3. 精修每日压力、当前日程、空档三张卡：先对齐真实数据和小屏布局，再增加装饰与动效。
4. 制作一张高密度“上周/累计”统计精品卡，验证各分区直达与数据可追溯。
5. 输出Flutter迁移的代表页对照样例和平台能力清单，再决定正式迁移范围与顺序。
