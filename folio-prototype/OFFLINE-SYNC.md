# 离线多设备同步（0.23-test.3）

入口：设置 → 设备与数据 → 离线同步。

1. 设备A选择“导出”，另存同步口令，再保存`.folio`文件。
2. 把文件交给自己的设备B，在B连接同一学校账号，选择“导入”并输入A使用的口令。
3. 读取并核对数量/来源时间后，点击“确认覆盖这台设备”。保留最近一次导入前的本机备份，可在同页恢复。

这是用户主动的离线快照覆盖，不是云账户、自动合并或后台同步。不会为此建立云服务、上传文件或收取服务费。学校账号使用现有本机学校账号标识核对；文件还需正确同步口令。它不引入新的学校身份认证，也不声称有远程设备白名单。当前宿主实现为原网页打包的Android版；Flutter/iOS尚无此导入接口。

## 数据边界

- 包含当前账号学校缓存、个人事项/作业覆盖、便签布局、卡片包、排课例外、学业/目标、学习记录与草稿、专注/复习记录和所列外观设置。
- 包含上述记录/草稿引用的本机录音，不能缺失或悄悄略过。音频在目标设备使用新ID，避免覆盖原文件；未确认录音草稿的记录指纹同步修正，保留原有并发冲突检测。
- 不复制其他账号档案、学校密码、Cookie、模型密钥/连接配置、对话历史与附件、设备权限、手机实际使用数据或原生通知投递状态。
- 同步前暂停专注计时，避免离线等待时间被误计。录音正在进行、保存未结束或草稿未写入时拒绝开始。
- 单次解密后JSON上限32MiB，四类学习记录合计20MiB；录音在JSON中用Base64表示，也占据32MiB额度。加密文件上限48MiB。超过上限完整拒绝，原记录不变；暂未实现大文件分卷。

## 实现与恢复

格式`folio-offline-sync`版本1。使用浏览器Web Crypto的PBKDF2-SHA256（310000次、每次随机16字节盐）及AES-256-GCM（随机12字节IV）。账号标识作为认证附加数据的一部分，仅在加密内容内保存账号；文件不含明文学号、文字正文或口令。默认口令由安全随机数生成，用户也可输入至少12字符的口令。算法API见[W3C Web Cryptography](https://www.w3.org/TR/webcrypto-2/)。口令不保存到配置或传入原生文件保存桥。

只读取/覆盖固定白名单。解密、格式、账号、录音长度与源记录版本均先核对，确认前不覆盖目标设备。预览后设备内容改变则拒绝使用旧预览。

先暂存新音频，再将导入前的Web缓存及四类原生记录快照写入应用私有IndexedDB，并写恢复标记。Android为四类记录暂存新分片，只提交一次总索引，使分片写失败时不会发布半套数据。随后同步Web缓存；任何一步失败用备份恢复两侧数据。未完成标记会使下次启动隐藏主界面，恢复后重新载入。备份/草稿仍是应用私有数据，不声称所有IndexedDB/localStorage内容均使用原生Keystore加密。卸载/清除应用会删除本机备份，已导出的文件由用户自行保管。

原生导出使用有顺序与大小检查的分片及系统文件保存器，用户选择保存位置；没有任意文件路径接口。不改学校服务端数据，不触碰源设备原录音。

## 目标与出分

`FolioGoal.retirePublished`仅匹配同学期和同课程ID。成绩发布后，无论目标页是否打开，都撤下该课已应用的目标、课堂提醒及目标带来的作业优先级；只保存旧目标作历史，不保存/泄露未揭晓分数。原总目标保持不变，已有成绩进入实际基准。剩余课程先保留原目标；“按实绩重新分配剩余目标”生成草稿，应用后生效。全部出分后不再留下待规划课程。重修仍遵循取首次/最高，不重复计学分。

## 验证范围

- 47个Node测试文件317项通过，包含加密往返、错误口令/账号、篡改/未来版本、白名单、目标退役与重修算法。
- 原生仓库9项与同步仓库/分片33项通过，覆盖每个暂存/索引写入失败点、版本冲突、非法文件名与分片顺序。
- 22项隔离浏览器检查：加密导出桥、模拟双设备、预览不覆盖、确认按钮、录音/草稿迁移、原生失败/缓存失败回滚、中断重载恢复、关闭目标页时出分联动、未揭晓成绩保护；23项日记/录音浏览器回归通过。
- 未有两台实体设备、真实Android文件选择/保存器、真机录音及实际学校出分场景的验收。测试使用虚构账号和合成音频字节。不能把模拟恢复当成真机杀进程验收。

代码入口：`offline-sync-core.js`、`offline-sync.js`、`offline-sync-guard.js`与Android的`RecordRepository`、`OfflineTransfer`、`MainActivity`。无新增第三方运行库。
