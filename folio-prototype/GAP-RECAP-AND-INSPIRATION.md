# 漏听回溯与灵感墙：方向与判断

2026-10-22。根据 Fish 本轮想法整理。本文确定产品边界、现状与后续讨论顺序，不是实现方案，也不代表功能已经上线。沿用现有网页打包 App，不启动新的客户端或另一套学习管理系统。

## 写死的原则

**这两个功能不做防走神，不做激励，不做统计。** 主动离开课堂主线去做另一件正事，由用户自己标记；不检测注意力，不评价动机，不统计漏听次数、专注度或处理率，不设打卡、分数、红点和催促。此边界针对新增功能，不要求移除 App 已有的其他功能。

**唯一的课堂组织单位是课次。** 同一课程在不同日期的课不能混成一条。“漏听回溯”和“灵感墙”是现有内容的两种入口/视图，产物必须归属具体课次，或进入已有事项与队列；不产生需要再次整理、再次完成的第二份内容。原有独立日记保留，不强行改造成课堂记录。

## 漏听回溯

解决“离开到回来之间讲了什么、从哪接上”，补缺口而非默认提供全课逐字稿。用户能在课次时间轴上看见缺口的位置与长度；进入缺口才看摘要和对应音频依据。短暂离开不是被系统判定的错误。

摘要先交代离开前接到哪里，再说明缺口内的变化，最后回答回来后从哪里继续。单独呈现三类老师明确表达的内容：**重点、考试相关、布置的作业**。某类没有依据就不硬凑；不把 AI 自己觉得重要的内容写成“老师强调”，不把“可能考”改成“必考”。作业提取先作为课次内容，用户决定加入现有队列，不自动多建任务。

听不清、对象指代不明、录音中断、只有局部素材，都直接说明。允许摘要不完整，不允许为了流畅补造事实。摘要应能回到对应片段核对；文字转写是原料，不是默认最终页面。

缺口与笔记属于同一次课，能补进该课次笔记的相应时间位置。不另建一个需要维护的“漏听库”。不做实时滚动字幕，不做自动判断离开，不默认生成整节逐字稿。

## 两个功能真正的交汇点

**离开时顺手记下三个字，回来时把那张灵感与缺口并排放在同一课次里。** 例如用户记“查傅里叶”，缺口标题可以是“查傅里叶时漏听的 5 分钟”。标题保留用户原意，不擅自猜测实际做了什么。

三个字是可选输入，不能成为开始标记的必填项；不填写也能离开，之后可以补。原灵感只保留一份，课次与缺口引用它。

用户进一步提问时，AI 可以比较“我刚查的内容”和老师这段所讲的关系，区分相同概念、先修知识、延伸内容或暂时无法判断。只凭三个字不能假装知道用户在别处看过的全文。这个比较由用户发起，不在每次返回时自动花费模型额度。

## 灵感墙

重心是处置，入口要轻。已在 App 内时，双击墙的空白即进入书写，不先选分类或弹确认框。内容先可靠暂存，不能像原先的易关闭弹层那样一误触就丢失。

**系统级捕获是必要方向。** 人在其他 App、路上或吃饭时也需要落点。首批至少选一个低成本、低打扰的系统入口；Android 分享菜单是优先评估对象，桌面小组件、快捷入口、悬浮球不要求同时做。入口回到同一份内容，不生出另一套系统便签。没有可确定课次时，落到现有事项的捕获入口，不能猜一节课强行挂上。

墙上的内容可以变为现有队列中的一个事项，也可以留在课次笔记，或被撕下。转为行动后不留下另一个“还要处理”的副本；已有队列负责后续安排，不另造墙专属排期。捕获念头本身不能默认塞进真正的作业列表，也不能自动获得既有队列的临期提醒。

撕下要有明确、短促的纸张物理感，但这是直接操作的反馈，不是奖励系统。误撕可以撤销；不靠动画结束把原文永久销毁。具体造型继续沿用现有纸张、折角和克制配色，另行打磨。

未处理内容从清晰到发黄，再变淡、沉下去；不自动删除、不悄悄转为已完成，打开后仍可读。允许密度和局部凌乱，用少量分区即可，不做无限画布和精细布局管理。老化时间、淡化程度尚未决定。

不推送、不红点、不显示“还有 N 条未处理”，不显示处理率与连续记录天数。**暂不采用打开 App 自动闪便签、浮出一张再消失**：这并非实现细节，而是有可能越过“不催促”的产品选择。墙可以自然地出现在用户会经过的现有课次或工作区中，是否增加其他露出方式以后再讨论。

## 对后续六条补充的判断

| 建议 | 本轮判断 |
| --- | --- |
| 离开时记念头，回来与缺口并排 | 纳入核心方向，记录可选，不额外挡住标记动作。 |
| 系统级捕获灵感 | 纳入必要入口方向，先选一个，不同时铺开四种入口。 |
| 给缺口带上前后文 | 纳入摘要质量要求；前后各半分钟只是候选量，不是保证足够的固定规则。可以用邻近音频或此前可靠结论，清楚区分背景与缺口本身。未录到的前文不能事后补造。 |
| 超过三分之一改整课总览 | 留作待验证的降级建议，不把 1/3 写成硬阈值。大缺口要明确覆盖不足，可给“本节已有材料概览”；没有整课材料就不能称为完整总览。 |
| 首页闪一下当作路过触发 | 暂不采用；自然露出可以讨论，自动闪现不直接纳入。 |
| 锁屏/通知栏完成离开、返回标记 | 保留为关键可达性方向；属于用户主动录音时的操作入口，不是催促通知。不承诺锁屏直接输入或所有设备都能同样操作。 |

| 补课、实验、临时课 | `FolioCourses.onDate` 合入 `FolioPersonalSchedule`，并使用既有课表排除规则 | 必须同样支持关联，不能只认学校预置课。调课、合并课段、重新同步后关联能否保持，需要专门核对，不能仅凭当前字符串 id 声称稳定。 |

| 笔记、日记、录音 | `learning-core.js` 的 `FolioLearningCore`；`learning-ui.js` 的 `FolioLearning`；`record-store-core.js` | 有 `journal/note/recording`，可存 `termId/courseId/sessionId`；`sessionId` 在录音自动关联时使用当天课次 id。已有课程笔记和按课程检索，但没有课次时间轴、缺口或墙视图。 |
| 记录与音频存储 | 正式学习记录为原生 `records.learning`，WebView 缓存 `folio-learning-v1`；草稿 `folio-learning-drafts-v1`；音频 IndexedDB `folio-learning-audio-v1` / `audio` | 可以复用现有笔记/音频，不应另建一套内容库。新关联与新内容将来须一并适配现有离线同步。 |

这里所说的“课次”必须连同学期判断；只按课程名或当天时间猜测不足以处理同名课、重叠、补课和调课。没有匹配不等于用户没有上课，也不能让一个未匹配的标记静默丢失。

## 目前不能绕过的能力缺口

**当前录音切到后台就停止。** `learning-ui.js` 在页面隐藏和 `folio-native-background` 时结束录音；Android 当前没有承担持续录音的前台服务。因此“离开去其他 App，回来仍有那段课堂声音”现在不成立。持续收音可靠性必须先证明，不能先做一张看起来能用的缺口卡。用户主动开启收音是前提，标记离开不等于授权偷偷全程录音。

**当前没有语音转文本，更没有已验证的免费本地转写。** 已有 AI 学习记录工具读的是文字，不会识别本机音频。转写能否真正离线、设备负担如何、后台录音和锁屏操作能否可靠运行，都需后续实际验证。不能把系统语音接口直接宣传为免费、离线、无限课堂转写。

缺口前后文、音频覆盖、时间定位和 AI 摘要必须形成同一条可核对的链路。先保证能取到正确片段，再讨论模型摘要；摘要只处理用户选择的缺口及必要背景，不默认上传全课或后台调用模型。老师的原话、AI 归纳、用户念头保持可辨。

## 推进顺序与成功判断

先核对课次关联在调课/同步后的连续性，以及用户离开 App 时音频能否可靠留存；同时确定一个系统捕获入口。随后只打通一条体验：离开并可选记念头 → 返回看见缺口和原念头 → 看摘要知道从哪接上 → 念头进入已有事项，或撕下。再根据实际课堂收音、真实使用感受细化墙和摘要。

不以统计面板验收。一节课后用户愿意回看缺口、看完知道怎么继续，才算回溯有用。两周后墙上有东西被撕下、有东西成为行动，而非只越积越多，才算墙有用。这是使用判断，不新增产品埋点、打卡或评分。
