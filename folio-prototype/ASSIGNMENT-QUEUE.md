## 用户已确定的规则

| 项目 | 新版要求 |
| --- | --- |
| 完整作业页 | 显示系统作业、自定义作业及明确入队的普通待办，可提前挂出、改日、完成；保留逾期与完成状态 |
| 个人待办 | 自己添加的事项，也可补充系统里没有的作业；所有待办默认不入队 |
| 手动入队 | 明确选择入队后参加同一便签队列，普通事项也可以，不限于作业类型 |
| 每周批次 | 下周一至周日截止的作业分配到本周；默认周五/六/日 25% / 45% / 30%，周一至周四在“扩展”设置；七天权重自动归一化 |
| 提前一周 | 指 DDL 所在周的前一周，默认周末，可扩展其他工作日；不是统一 DDL 减 7 天 |
| 挂载保留 | 分步挂上，未完成继续堆积；跨日、逾期或比例变化不会自动取下已挂便签 |
| 完成 | 从便签队列取下，原作业或待办仍保留完成状态 |
| 手动改日 | 改成未来日期时先取下，到那天再挂；不改变 DDL；手动日期优先 |
| 临期 | DDL 前两天升级提示；最终变色或卡通火焰样式继续由用户指定 |
| 通知 | 先做 App 内队列，手机系统通知以后决定 |
| 来源跳转 | 优先具体作业；无有效深链时打开学在浙大，不猜深链格式 |

截止日、挂载日、入队开关和完成状态分别记录。退出队列不删除待办。

## 目标重要课程的提前策略（2026-10-17）

目标页保存并应用后，目标绩点大于等于重要门槛的课程加入优先名单。只调整未挂出、未完成、非手动日期的已入队作业：重要课先获得较早名额，周日的改为最晚周六，周五自动挂载在 14:00；原比例允许的更早工作日保留。重要课截止前 3 天进入紧急，普通仍为 2 天；详情与列表有小火焰提示。目标草稿不触发，停用方案恢复普通未来分配，已挂出和手动日期继续保留。正式藤蔓及卡通火焰视觉仍待设计，见 `GOAL-FEATURES.md`。

## 便签栏不是作业页

它贴在首页右边 **2×2 工作台的右侧屏幕边缘**。一根绳子从下到上，便签从上到下依次贴上。工作台再次从右向左滑动可收起便签栏。点击便签展开便签样式的信息，并提供来源跳转。

位置、方向和手势已明确；四个模块、绳子质感、便签详情及火焰细节仍待用户指导。本轮没有提前绘制这些视觉。

## 当前可操作原型

- 作业页：10 份教务示例，默认本周 2 份已挂、下周 8 份待分配；全部 / 未完成 / 已完成筛选。
- 待办页：新增普通事项或自定义作业，入队默认关闭，详情里可改变入队状态。
- 详情：提前挂出、指定日期、完成、学在浙大入口。使用已认可的白色分组弹层，尚未画成便签。
- 比例自动归一化到 100%；不能为负或全部为零；8 份默认分成 2 / 4 / 2。整数采用最大余数分配，相同余数优先较早日。扩展折叠不清除周一至周四的设置。
- 作业页有列表和未来两周热力图：一科一行、一天一格，只按未完成作业的 DDL 计数；橙色 1 份、红色 2 份及以上，灰色 0 份；完成立即刷新颜色。上方汇总每日总量。自定义作业及明确入队的普通待办统一归到“自定义”行；自定义作业未入队也展示。
- 课程名单行滚动：超宽时先停 1.5 秒，缓慢滚到末尾，停 1.5 秒后回到开头循环；短名静止，滑入可见区域重新从开头开始。点击仍可看全名与条目。课程区独立滚动、无滚动条，有下方未显示课程时提示数量，到底消失。日期轴与总量行固定，底部解释文案移除。
- 已完成记录不删除，可从列表或点击课程名查看。全部 / 未完成 / 已完成只用于列表，热力图不显示这些筛选，也不受列表选择影响；“合计”行表示所有课程当天的剩余数量。两周窗口外的待完成作业可转列表查看。
- 日期控件改为页面内月历，限制在手机容器内，不使用浏览器原生弹出窗口。
- 示例日期模拟跨日挂载；往回切也不会撤销已挂条目。重置示例才恢复初始状态。
- 操作保存在当前浏览器本地存储，不与真实账号、服务器或手机通知连接。
- `calendarEntries()` 提供截止事件和挂载事件两类独立数据；日历界面及教务作业与待办互相引用的呈现仍待设计。

页面上的每日配额是学校下周作业按比例计算的目标数量。手动安排、已挂载保留及个人待办入队后，实际数量可以不同。

## 原型临时边界策略

以下是演示采用的实现策略，不是用户已确认的最终规则：

- 按 DDL 从早到晚分配，明确入队的普通事项参加同一截止周批次。
- 比例调整只计算尚未挂出、无手动日期的条目。完成条目保留在批次基数中，防止完成一份导致其他日期漂移。
- 自动挂载日已过去的新条目在下次计算时挂出，已有条目保留。
- 无 DDL 的入队待办等待用户指定挂载日，不猜截止日期。
- 临期按日历日算；真实教务有精确时刻时，再决定是否使用 48 小时。
- 刷新缺失、改 DDL 后未挂条目的重分配、提交状态与本地完成的对应关系，在真实数据接入时确认。

## 当前源码缺口

`Todo` 只有 ID、名称、课程、截止时间；需要独立本地完成、入队、挂载和来源状态。教务刷新替换作业集合，应按稳定 ID 保留本地状态。原日历主要处理固定任务与课程；需接入作业 DDL 和挂载事件。原后台截止前 24 小时的一次通知不能直接沿用为分批推荐。
