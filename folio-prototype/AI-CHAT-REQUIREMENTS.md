# 首页 AI 对话：前端原型与后续接入约定

更新：2026-10-16。记录用户本轮设想；不是已接通模型的声明。只修改浏览器原型，不修改 Flutter。

## 已做的前端

- “下一节课”信息条保留在空白首页输入卡片顶部，进入对话后隐藏，未删除课程组件或示例。用户 2026-10-15 补充参考图，明确允许隐藏。
- 参考补充截图：输入文字或带附件时，右下角拍照按钮替换为赤陶色发送键，空输入恢复拍照；相册入口及加号中的相册/拍照始终保留。发送键不再另占输入文字区域。
- 对话页用户消息采用无尾角的浅暖灰气泡，助手正文在下；顶部有新建对话及历史，底部输入卡片固定。输入框随多行文本增长至上限，再在内部滚动且不显示滚动条。
- 消息区独立滚动，离开底部时显示向下的“回到最新消息”按钮。翻看历史时，打开/关闭面板、改变模型等重绘保留阅读位置；主动发送和点击定位会回到最新。底部跟随状态下，输入框变高或窗口尺寸变化时继续跟随；翻看旧消息时不抢位置。
- 参考图的“生成中三点 / 停止按钮”记录为后续真实请求状态：接入模型后，发送期间右下角切换停止键，停止应中断当前请求并保留已发送消息、已收到内容及待确认提案。当前仅同步本机保存，没有真实流式生成，不添加假等待动画或虚假的停止请求。
- 右下角改为相册、拍照，移除麦克风与语音按钮。加号菜单包含文件、相册、拍照；快捷命令留入口，具体内容后续设计。
- 输入文本或选择附件后可保存一条本地消息。当前助手文字是明确标记的流程说明，不是模型回答，不识别图片、不联网发送。
- 模型胶囊可打开厂商、模型与思考强度选择；当前为未连接/通用/推理的示例选项，不冒充厂商返回的模型列表。设置在本机保存，每条用户消息保留发送时的配置快照。
- 顶部历史按钮及侧栏“对话历史”可恢复会话；新建对话不覆盖旧消息、未发送文字和附件。没有自动清除历史或未确认修改。
- 对话与草稿元数据用 `localStorage: folio-chat-v1`；文件原始 Blob 用 IndexedDB `folio-chat-files / files`，不把大图 base64 塞进 localStorage。单文件暂限 20 MB。附件仅本机保存，刷新后恢复缩略图；清除浏览器站点数据会删除本机记录，尚无云同步。
- 助手消息下方显示缓存命中输入、缓存未命中输入、输出 token 记录。当前没有真实 usage，显示 `—`，不显示编造数字或费用。已有字段为 `cacheHitInputTokens / cacheMissInputTokens / outputTokens`。
- 本地助手说明下有“预览 DDL 确认窗”，明确不从消息/图片推断。可填标题、独立内容、截止日/时刻、待办或自定义作业、是否入便签队列；截止日沿用页面内日期选择器。
- 修改作为提案持久保存，收起、遮罩点击、Esc、换页面、换会话和刷新均不舍弃。首页显示待确认入口，历史里标记待确认。只有“舍弃”终止提案；只有“确认添加”才写入现有本地待办，同步作业/日历的既有投影。
- 固定提案 ID 作为本地任务 ID，确认失败可重试，不重复添加；必填标题与日期使用现有待办校验。确认后保留对话记录和操作结果。

## 后续真实模型接入（用户要求，尚未实现）

用户于 2026-10-16 明确取消独立搜索页面，将搜索整合到 AI。课程、作业、待办、考试等内部查询沿用下面的按需读取机制；查询结果可打开对应已有详情。查询属于只读操作，不生成修改确认窗；如进一步要求改动数据，仍须走可编辑提案与明确确认流程。当前不制作独立搜索入口，不用固定示例回复冒充已查询到真实数据。

1. **模型发现**：从用户选定厂商/兼容服务实际获取可用模型。保留模型原始 ID、厂商、分页和刷新/失败状态；不能硬编码一份看似实时的模型列表。思考强度、预算、图片/附件和其他参数按该模型实际能力显示、映射及校验，避免给所有模型强套同一参数。凭据管理方案另定；不在前端源码/localStorage里放真实密钥。
2. **系统提示词**：具体提示词由用户后续设计；本轮不擅自写定人格、业务权限或快捷命令。需要支持可版本化提示词及会话恢复。
3. **按需读取**：首轮提供小而稳定的接口/工具定义、参数 schema 和模块说明，由模型结合用户指令选择要读的课表、日程、待办、作业、考试、成绩等。不要默认一次灌入全部内部数据。工具响应需限字段/时间范围/分页，复用已读结果并记录数据版本，变化后失效；缓存不等于永远读取过期数据。
4. **写操作分两阶段**：模型先生成结构化修改提案（操作类型、目标 ID、字段、来源、时间/时区及冲突提示），前端展示可编辑设置窗。例：图片 + “设个 DDL” → 模型读图与按需读取 → 形成提案 → 用户可修改 → 明确确认后才提交；舍弃则不写业务数据。模型不能先写再弹窗。
5. **提案保活**：服务端/客户端应有稳定提案 ID、会话 ID、原消息与附件引用、草稿字段、状态及更新时间。点击外部、最小化、暂时离开 App、页面路由变化或重启均保留，直到明确确认/取消。后台执行与网络重试也不能擅自丢弃。确认使用幂等键及目标版本校验，提交失败保留字段；冲突需重新核对。
6. **持久会话**：保留消息、附件、工具调用/结果、模型及参数快照、提案状态和真实 usage；支持切换会话并继续。后续再决定云同步、删除/导出及隐私管理，当前仅本机原型。
7. **用量与缓存**：逐回复记录厂商原始 usage 及标准化字段：输入总量、命中缓存输入、未命中缓存输入、输出、推理 token（厂商若单列）、可选缓存写入。未知与真实 0 必须区分；不凭字符数估算后当作真实值。工具调用多轮按请求记录并汇总到本次回复，避免输出 token/推理 token 重复计数。厂商是否把缓存写入含在输入内需由适配器明确；不支持缓存统计时显示未知。费用/缓存政策以后根据选定厂商另接。
8. **缓存组织**：稳定提示词/工具 schema 前缀与变化的用户消息、按需数据分开；真实命中由厂商返回，不因本地复用而声称命中计费缓存。保持原始事件与请求 ID，便于排错及对账。

## 尚未设计 / 不在本轮

真实识图和 AI 回答、厂商端点/密钥表单、系统提示词正文、快捷命令内容、真实内部工具和写事务、云同步、系统通知。移动端拍照入口使用浏览器 `capture=environment`；桌面通常打开图片选择器，需在最终 Android 端接入真正的相机/相册权限与生命周期。

## 实现位置与验证

- `chat-core.js`：会话、消息、提案与待办映射；`chat-ui.js`：入口、附件保存、历史、选择器、持久确认窗；`chat.css`：视觉。
- `node --test chat-core.test.cjs`：空消息、真实用量缺省、序列化、多会话草稿、待办验证和固定 ID。
- 浏览器需验证：360/390/430 宽不溢出；附件刷新仍可见；确认前待办不变，确认后仅新增一次；遮罩/Esc/收起/切页/刷新保留草稿，舍弃不写入。
