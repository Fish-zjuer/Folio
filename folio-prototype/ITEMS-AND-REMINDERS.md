# 课程安排、显示位置与多个提醒 · 2026-10-20

本轮基于外部已发布的0.17源码。尚未打新APK、未推送或发布。本轮只改Web运行逻辑，Java宿主及已发布物不变。

## 用户明确的需求

补排实验应当作为上课安排显示，不能被迫成为作业/待办或占便签配额。确认时可多选显示位置并独立决定入队。同一记录可以有多个提前提醒。时间未知时能先确认保存，AI不得编造00:00或使用`--:--`作为有效时刻。

## 实现

- 新个人类型`lesson`：上课／实验。关联现有课程时复用courseId、termId及颜色，不新增课程目录或学分。`create_lesson`为AI独立草稿操作，`lessons`为检索入口。旧todo/homework/event保留。
- `placements`可选数组：`calendar`日程、`timetable`课表、`todos`待办列表、`homework`作业页、`home`首页当天栏。缺省采用类型默认值，显式空数组表示不放进这些视图；仍可通过“全部个人记录”找回。`queued`独立，显示位置不改变类型和学业统计。
- lesson默认日程/课表/首页当天栏。经过`FolioCourses.onDate`作为个人课程块投影，支持单次、重复、跨午夜、无校历时的明确个人安排。点开进入个人记录编辑，不进入教务排课删除界面。手动排课标签为“单次”或用户的重复规则。
- 工作台课程队列独立于纸便签，课程样式、地点/时刻，默认当天挂出；未定日期且选择入队时立即可见。普通便签配额和作业集合不再因为queued而吞入课程/普通待办。
- `reminderOffsets`是0–525600的整数分钟数组，最多12个，去重且按触发先后排列；输入接受中英文逗号、顿号、分号或空白。旧`reminderMinutes`单值可读，写入同时保留首个值用于兼容。
- 提醒以明确的开始时刻或截止时刻为锚，跨日分别计算。完成/学校已交/重复模板不生成提醒。**当前仅有App内提醒列表与触发时间计算，没有原生后台闹钟或进程被杀后的系统通知。** 不要宣称已经支持后台准时推送。
- `timeMode=pending`可配`scheduledDay`或空日期；保留提醒配置但不触发。已知日期放当天未定时区及周课表的未定时列表，不塞到00:00。补齐时间后同一id继续使用，提醒恢复。
- AI的`日期T--:--`被规范化为pending并提取有效日期；明确非法时间如25:00仍拒绝。AI确认和个人编辑共享显示/提醒表单；草稿仍需用户确认。学校原始字段保持只读，同步保留本地显示/提醒设置。
- Widget API v1新增可选字段，没有改变注册契约。courses快照提供最少的个人排课元数据用于缓存失效；SDK统计读取不随界面隐藏而抹掉课程数据。原型卡片SVG/CSS未改。

## 后续可细化

- 针对不同记录设计更短的确认表单、提醒快捷多选及自然语言时间输入。
- 后台系统通知需独立设计Android调度/权限/重启恢复，不能复用仅用于成绩更新的`app.notify`冒充通用闹钟。
- 没有日期的待定记录无法定位到日历某一天，通过全部个人记录或显式入队访问。课表的明确时间仍遵循现有13节显示范围，深夜事项可在完整日程和首页当天栏查看。
