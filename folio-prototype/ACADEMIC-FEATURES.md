# 学业总览、成绩与独立刷新

更新：2026-10-15。前端可操作样例，不连接教务、不修改 Flutter。数据为虚构示例，不是用户截图中的个人成绩。

## 页面和入口

- 菜单“学业”：所选学期、课程/作业搜索、成绩、课程、作业与实践记点摘要。
- 成绩包含五分制绩点、4.3/4.0 两种绩点、已知已获学分、主修均绩/学分、百分制均分及出分数量。可选择具体学期或全部学期；全部学期的成绩列表和下方课程摘要均按学期分组，课程统计不混在一起。
- 课程/学分/考试数量复用已有课程、考试仓库；秋冬两段课时按各自选定的完整两周逐日计算，显示日期区间，复用教学单双周、起止/指定周规则。缺失校历的学期不编造课时。
- “成绩”页支持查找、学期切换；已揭晓课程可设置本地规则。课程详情使用同一揭晓状态，返回时回到来源页。选择的学期与范围保存在本机。
- 实践记点内嵌在学业页下方，第二／三／四课堂切换、已计入和未计入项目列表、详情弹层均有本地初稿。美育／劳育尚未获取；毕业进度、趋势、目标测算及差异历史尚未开发。

## 本地方案：核心课与主修

- “教务原始”和“本地方案”可切换。原始成绩对象不被手动设置修改。
- 用户可将课程标为核心课，在本地方案中 **绩点 ×1.2**，之后按原学分加权平均。五分制、4.3 制及 4.0 制分别计算，不把加权结果强行截断到原始上限。
- 主修归属可选按教务、本地计入、本地不计；可用于用户自行认定的可替代课程。本地标记不是教务审核或正式培养方案认定。
- 核心系数不改变课程学分、原始百分/等级成绩及百分制均分。即 `本地 GPA = Σ(原始绩点 × 核心系数 × 原学分) / Σ(计绩点的原学分)`；非核心系数为 1。
- 保存后切到本地方案以展示变化。单门可以恢复教务设置；设置菜单可全部恢复，并可撤销最近一次本地修改/恢复。保存最近十次修改前的标记供撤销。
- `localStorage: folio-academic-v1` 中 `overrides` 按成绩稳定 ID 单独保存，和 `cache` 分离；教务刷新只更新快照，不能覆盖核心课/主修标记。

## 可选的成绩揭晓

- 默认开启，新成绩用暖色纸胶带遮住，带轻微纸纹、撕边和倾斜。列表点击即可轻轻揭开；课程详情点击胶带进入同样的揭晓弹层。没有大封面、折角或情绪化提示。
- 尚未揭晓的原始分数、等级、派生绩点不会先写进列表或课程详情的 DOM/可访问名称；相应范围只要还有未揭晓成绩，均绩、学分等数字摘要也一起隐藏，避免间接透露结果。此为前端展示保护，本地缓存仍保存原始数据，不是加密功能。
- 二级制合格/不合格同样需要揭晓；未出分记录保持“待录”。关闭弹层、点击外部或选择“稍后再看”不视为揭晓。
- `reveal.seen` 按稳定成绩 ID 保存已看过的结果指纹。原样刷新不重新遮住，成绩更正会重新遮住；修改课程名、本地核心课或主修归属不触发。
- “揭晓设置”允许关闭，点击保存才生效；关闭时已有及后续结果直接显示。再次开启不遮住已经公开的结果，之后的新出分或更正仍会遮住。尊重减少动态效果偏好。
- “刷新演示”新增模拟微积分出分/更正选项，仅修改本地虚构样例，结果可持久保留，普通刷新不会退回“待录”。

## 百分制、五级制与二级制

- 百分制、五级制均进入绩点。五级制保留“优秀/良好/中等/及格/不及格”原文；不及格仍计绩点分母，不能因为未获学分而排除。
- 水测“合格/不合格”为二级制，两种结果都不进入 GPA 分子或分母；编辑器禁用此类课程的核心绩点系数。是否获得学分独立判断，不因不计 GPA 就直接认定不计学分。
- 水测样例的学分和已获学分资格未给定，因此显示待确认，并提示未包含在学分合计中，不虚构为 0 学分或已经获得学分。
- 用户已提供 **五级制→绩点** 清单：优秀/A 4.5、良好/B 3.5、中等/C 2.5、及格/D 1.5、不及格/F 0；百分制按 95/92/89…60 的整数区间映射。两种制式分别直接转换，不能将五级制先转百分再算绩点。完整表及边界见 `GRADE-RULES.md`。
- 原版 `lib/model/grade.dart` 的 **五级制→百分制均分** 映射仍独立保留：优秀 90、良好 80、中等 70、及格 60、不及格 0。用户表并未规定反向百分值，不混作绩点规则。
- 原版 **五分制 GPA** 直接读取接口 `jd`；真实接入需要保留并核对原值，不用本地换算静默覆盖。原版 >4.0 的 4.3 制转换另有 `5→4.3、4.8→4.2、4.5→4.1、4.2→4.0` 表；传统 4.0 制封顶 4.0。本地样例通过本轮统一换算函数生成派生值。
- 未知等级、缺失绩点、待录都不得伪装成已出分的 0；真实接入时应标为待确认/不完整，并说明均绩缺失范围，而非覆盖已有完整记录。

## 独立刷新与缓存

- 每张卡片有独立状态。刷新时只在该卡片覆盖轻白底和转圈；完成后恢复内容，成功显示短暂绿色对勾并自动消失，失败显示赤红三角、白色感叹号。
- 全部刷新同时启动各模块，不顺序弹窗、不显示内部日志；同一模块/学期的进行中刷新合并等待，避免连续点击发起重复请求。切换学期后旧请求仍写回它原来的缓存键。
- 失败、异常空成绩、未完成响应、非法记录与重复 ID 均保留旧快照及上次成功时间，不清零。成绩/课程新片段按 ID 合并，缺席记录不当作删除。真正权威删除的确认协议留待真实接口阶段设计。
- 完整且明确允许为空的作业响应可表示确实没有作业；请求失败或不完整不可以。不同模块的成功时间及失败标志独立保存。
- 用户点击失败图标，会短暂膨胀/碎点消散后隐藏；也可“清除刷新提醒”统一扫除。该动作只清除提醒，不修改数据、不改成功时间，不把失败伪装成成功。清除状态保存在本机，新一次失败可以再次提示。
- 当前不自动淘汰最后一份有效快照。清除浏览器站点数据会清除原型的本地保存，尚无账户云同步。

## 如何验收刷新效果

点击“本地示例 · 刷新演示”，选择要失败的卡片，或选择“成绩异常返回空列表”，再开始演示。每个模块的延迟/结果是显式的本地演示，不是网络请求。普通刷新按钮也只读本地样例。

已核对原仓库：`Scholar.setScholar` 对非空成绩和主修数据有保留旧值的守卫，课程支持部分合并，异常捕获也会保留数据；但不能据此认定所有模块和空结果都安全。旧作业路径在无错误标记时会直接赋值空列表。后续迁移需要对实际接口的完整性/错误/合法空状态统一建模，并用本轮缓存测试约束。
