# 目标均绩与课程目标分配

更新：2026-10-17。已制作可操作的本地原型，从侧栏“目标”进入。调试和课程目标是同一页面的两种状态；真实教务与 Android 接入尚未进行。原“接下来”模块暂缓。

## 用户明确的功能

- 新增目标页面，根据当前均绩、目标均绩和本学期课程及学分，反推课程目标组合。
- 允许部分课程目标较低，把需要提高的部分分配给其他课程；不要求所有课程拿最高分。
- 尽量给出略高于目标、带少量余地的组合；无法达到时允许展示低于目标的方案，但必须明示未达标及差距。
- 给出多套可选组合。若同学分课程可以替换，例如三门 3 学分课中只需要两门达到高目标，由用户决定具体哪两门。
- 用户选定方案后，高目标课程要在上课等相关场景提醒用户认真听课。
- 模拟目标与真实成绩分开保存；不能覆盖教务原始成绩。

## 用户补充的两阶段流程（已确认）

- 计算类型分开：总均绩、学期均绩、主修均绩。非主修课程可少投入，但通常不能挂科。
- 首次进入先显示调试页，不采用最初提出的“顶部指标、中部方案、底部调整”的单页布局。
- 调试页先选类型、设置目标与最低可接受绩点。最低可接受绩点因人而异，可为 4.5、3、1.5 等；剩余课程不低于这个底线。
- 按学分展示分配卡，显示课程数量、冲高与剩余分配情况；用三横杠作为拖拽柄，向上优先高绩点，向下较低。默认大课优先冲高。
- 不同学分可组合贡献：例如一门 3 学分与三门 1 学分并非互斥，算法须共同核算。
- 确定后转换为具体“课程目标”页面。后续直接细调课程数值，不依赖拖拽；右上角一个小窗口随调整实时显示预计结果，当前均绩无需占主要位置。
- 重要课的作业要优先早挂、早完成；即使下周四截止，也尽量安排在前一周周五下午或周六。不得覆盖已挂载、手动指定日期，也不宣称已完成作业。
- 用户最终明确：算法先按学分分配，默认高学分优先；同学分内水课与硬课由用户决定。目标较低时允许剩余课程只守底线，不替用户额外加码。
- 重要课单独设门槛，课程目标绩点 **大于等于** 门槛即为重要课；普通作业提前 2 天进入紧急，重要课作业提前 3 天。

## 已核对的现有规则

- `academic-core.js` 已按用户提供的表实现百分制与五级制到五分制绩点的映射。使用这些离散档位，不把任意小数绩点当成可取得成绩。
- 百分制最高 5，五级制优秀为 4.5；合格／不合格课程不进入 GPA 分子和分母。未知成绩制式不能默认按百分制处理。
- 本地核心课规则是绩点乘 1.2，学分分母不变；主修归属可本地修订。目标页默认不加核心倍率，可在“计算基准与规则”开启；课程设置中的目标专用覆盖不改写成绩页规则。
- 当前均绩之外还需要已计入 GPA 的学分或加权总分，不能仅凭 4.4 与 4.45 两个数字计算。
- 未来课程表中有 5.5、1.5 等非整数学分，计算不能截成整数。

## 计算与状态要求

统一口径下，设已有加权绩点总和为 S，已计 GPA 学分为 C，未来课程学分为 c_i，目标档位绩点为 p_i，选用的核心倍率为 w_i：

`预计累计均绩 = (S + Σ(c_i × p_i × w_i)) / (C + Σc_i)`

- 只有已计入的历史成绩进入 S/C，待录不当作 0。当前学期已出分的课进入已知部分，不再作为未来课重复计算。
- 课程 ID 用于关联真实成绩、课程表与目标；学期和纳入课程范围必须明确。
- 算法先给全部课程满足底线的最低可用档位，再按优先级提高课程目标。底线本身已够用时不额外加码；否则尝试留 0.01 均绩余地，并受离散档位约束。不是寻找全局最小超额或保证现实可取得分数的优化器。
- 全局底线不低于 1.5；逐课最低值不能绕过全局底线，最高默认采用对应制式最高档。可在课程设置更改上下限。
- 若最高档也无法达到，显示可达上限与差距；不把四舍五入后接近目标显示成达标。
- 相同学分但制式、倍率、上下限或锁定状态不同的课程，不能无条件互换；每次替换重新计算。
- “必须”仅用于确有约束证明的条件；普通候选组合标为建议，不暗示系统能保证获得该成绩。
- 结果属于情景测算，不自动判定保研资格。打开页面或学业数据更新时重新投影；已保存的提醒仍沿用明确应用的方案，重新保存才更新。
- 已启用隐藏成绩或存在未揭晓成绩时，目标页的当前值、组合结果和差额不能绕过现有隐私／揭晓保护间接泄露分数。

## 提醒与保存

- 只在用户明确选用并保存方案后，向关联课程添加目标提醒；仅浏览候选组合不改变其他页面。
- 课程列表、详情与日程显示“目标 X · 这节课认真听”；周课表用克制的边框与角点标记，点击仍打开原详情。按学期与课程 ID 关联。
- 作业优先仅影响已入队、未完成、未挂出、未手动指定日期的条目。优先课程先分配较早名额；原应在周日挂出的重要作业提前至周六，周五的自动重要作业在 14:00 挂出。用户设置了更早工作日时不延后。
- 优先课程匹配先用课程 ID，旧作业无 ID 时用当前学期唯一课程名，并限制截止日在学期日期内；正式接入应补全稳定课程和学期 ID。当前无校历的旧学期不猜测时间范围。
- 不更改 DDL、不取下已有便签、不改变待办入队开关；重要作业详情和列表显示提前 3 天提醒，紧急列表用小火焰标记。藤蔓便签视觉仍未设计。
- 提醒可取消／替换，不修改课程时间，不恢复旧自动时间规划，不默认增加手机系统通知。
- 本机持久化目标、口径、课程选择与选定方案；与正式成绩缓存分开。

## 当前原型与保存

- 初始为独立示例，标明非教务数据，示例基准为 4.4 / 100 已计 GPA 学分，方便调试。示例课程制式、归属均为可编辑的假设，不当成真实教务字段。也可手动改基准或切到学业缓存。
- 总均绩使用截至选定学期的已知成绩；学期均绩只用所选学期；主修均绩仅纳入主修，但非主修课程仍有保底目标。已出分课计入基准、从待分配课程移除，二级制不入 GPA。
- 学业数据模式尊重隐藏与揭晓保护，阻止通过预计结果反推出成绩。主修归属缺失时需在调试页的课程设置确认；缺失制式目前标为估算，需用户确认后用于真实规划。
- 调试页有三类选择、学期、目标、最低绩点、重要门槛；拖学分组调整优先级，同学分可“优先这门”。支持鼠标／触摸拖动及上下方向键。
- “确定课程目标”进入逐课编辑：直接选离散绩点、查看对应分数段／五级文字、交换同学分课程目标、改目标专用课程规则。更改一门不会自动改其他课程，右上角实时重算。
- `localStorage: folio-goals-v1` 分开保存草稿和 applied 方案。字段更改、离开页面和刷新保留草稿；“保存并应用”才更新提醒。可停用已保存提醒，保留草稿。
- `goal-core.js` 是独立测算函数；`goal-ui.js` / `goals.css` 是界面；`FolioAcademicUI.goalData` 提供受保护的缓存投影。队列策略在 `homework-queue-core.js` 中接受可选目标规则，旧调用无规则时行为不变。
- 测试覆盖未达标但舍入相同、跨学分优先级、非整数学分、三种制式、核心倍率、锁定、底线、提醒隔离与重要作业提前安排。后续真实数据仍需完整学分、制式、重修等校方口径核对。
