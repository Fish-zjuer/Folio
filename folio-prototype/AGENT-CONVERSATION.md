# Agent 对话与过程区（2026-10-22，未打包）

原网页主线。日记、录音暂时从可见界面隐藏；代码、正式记录、草稿和音频均保留，课程笔记仍开放。学习记录入口改为“课程笔记”，横向浏览称“笔记”，课程详情只列笔记。历史录音/日记不混入列表、草稿入口或 Agent 的学习记录工具，也不能经旧编辑回调重新打开；完整数据仍由原学习记录仓库保存，并继续参与既有离线同步。

## 过程展示

- `agent-progress-ui.js` 与 `chat.css` 负责显示，`chat-ui.js` 连接真实 Agent 事件。折叠时只显示公开摘要/计划的第一行；未提供时使用实际处理状态。不再把每个工具一概写成“查看相关信息”。
- 标题17px、字重500，过程正文14px、类别11px；优先清晰的中文无衬线字形。标题和展开文字使用同一左起点，回复两侧向内收8px，过程另留2px。浅色灰字/土橙工具色、深色对应配色成对定义。
- 展开最大104px，约三四行，生成时跟随底部；用户主动翻到上方则可停留，重新打开生成中的过程会回到最新。顶部已有内容使用渐隐。完成或停止后不自动全部展开，也不强制关闭，仍可自行滚动，重新渲染保留展开状态和阅读位置。
- 区分公开摘要、公开计划、工具和请求状态。工具显示具体名称、调用中/完成/未完成以及失败原因。工具结果过大、空结果和被拒绝均在界面和模型收到的结果中一致标为失败；停止不再被吞成工具错误后继续请求模型。
- 当前接口是 Chat Completions、`stream:false`。摘要在一次接口响应返回后更新，工具在执行前后更新；不是逐 token 的思维文本流。只显示接口明确提供的 `reasoning_summary` 或工具调用前的公开说明，不显示、持久化或推测 `reasoning_content` 内部推理。接口没有公开摘要时只有真实过程，不能制造一段思考假文案。必要的供应商推理协议字段仍只在本次内存请求上下文中传递。

## 可调额度

设置 → **Agent 对话**；模型与 Agent 窗口也有入口。保存于本机 `folio-chat-v1/settings.agent`，从下次发送生效，进行中的任务使用发送时快照。恢复默认仍需点击保存，不立即修改设置。提高额度会增加模型用量。

| 设置 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| 携带的历史对话 | 8轮 | 1–32轮 | 一次用户提问及其回答算一轮；从用户消息边界截取，不以孤立的旧回答开头。 |
| 单条文字长度 | 16,000字 | 2,000–64,000字 | 发送给模型的单条文字/文本附件截取范围；不裁掉本机原文，不代表模型输出token上限。图片/PDF仍使用原附件总量限制。 |
| 每次任务最多请求 | 8轮 | 1–32轮 | 包括处理中间工具结果的模型请求。超过时保留草稿、用量和原因，并指向设置。 |
| 每次任务最多修改 | 8项 | 1–32项 | 同一次用户请求产生的待确认草稿预算，事项和设置共用；重复草稿仍去重。 |

每次模型响应最多6个工具的原有限制保留。设置不改变工具白名单、成绩读取授权、学校原始字段只读或“草稿→确认→落盘”。增加轮数不能保证供应商不拒绝请求，也不会绕过服务端上下文、余额或输出限制。历史仍存于本机，不因发送窗口变短而删除。原生模型凭据和别名配置不受这组设置影响。
